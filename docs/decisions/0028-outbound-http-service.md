# 0028 — Bounded outbound HTTP service

## Decision

Expose `HttpService:RequestAsync(Options)`, `GetAsync(Url)`, and `CancelAll()` through reflection. HTTP requires only `network.client`, uses the existing Asio worker, paced dialer, host address/port policy, pending task references, and owner-thread result materialization. No backend or raw connection object enters its API.

The initial profile is encoded plain `http://` URLs, strict HTTP/1.1, and buffered request/response bodies. Requests use a fresh connection with `Connection: close`; redirects, retries, cookies, proxies, compression decoding, pooling, and TLS are deferred. This avoids replaying potentially non-idempotent methods and keeps resource ownership explicit while hosted persistence is implemented separately. The URL authority supplies Host; LUI owns all framing. Application fields cannot provide Host, Content-Length, Transfer-Encoding, Connection, Trailer, TE, Upgrade, Expect, Keep-Alive, or Proxy-Connection, in any casing. CR/LF and other forbidden control bytes fail before network I/O. Request and response serializers validate their generated header sections with the same parser contract.

Request bodies are binary string/buffer values capped at 1 MiB. The response body defaults to 1 MiB and can be configured from zero through 8 MiB. A request deadline defaults to ten seconds and is configurable from 1 to 60000 milliseconds; it covers DNS through the final response on the worker. Informational replies are separately bounded to eight, each subject to parser header limits. Upgrades fail. The client never exposes partial or malformed data, and closes each socket on every terminal path. Framing/content rules follow [RFC 9112 §6.3](https://www.rfc-editor.org/rfc/rfc9112.html#section-6.3); body-free statuses and method semantics follow [RFC 9110](https://www.rfc-editor.org/rfc/rfc9110.html).

One runtime holds at most 32 HTTP requests/results until scheduler delivery, within the shared 128-operation ceiling. These native buffers are separately bounded; they are not charged to the Luau allocator's memory quota. Completion produces immutable response tables with binary string content and ordered duplicate-preserving field arrays. HTTP status failures remain responses; I/O and protocol failures throw stable `[LUI:Http] Code` errors without platform descriptions. The shared async guard remains `[LUI:Network]`.

`CancelAll()` records the latest request sequence and posts a coalesced worker barrier, completing still-active matching calls once with `Canceled`; already completed results stay queued. Repeated calls cannot create an unbounded cancellation-job queue. Starts also check the published cutoff, so coalesced calls include requests submitted between barriers; calls after the latest cutoff are unaffected. Teardown stops and joins the worker and releases outstanding references without running Lua again. Dial completion callbacks hold weak HTTP references to avoid cycles when teardown discards pending handlers. Requests/responses cannot leak native handles.

The internal response serializer prepares the hosted layer: application framing overrides are rejected; ordinary replies use fixed lengths, duplicate fields retain order, and HEAD omits content while retaining its representation length. 204 and 304 emit no length/content; 205 emits zero length. Only final status codes 200–599 are emitted by this serializer. Hosted routes and persistence remain pending.

## Verification

Native peer tests exercise the public service with `network.client` and without `network.raw`. Coverage includes fragmented informational/binary replies, duplicates, chunks/trailers, EOF, HEAD, malformed framing, limits, deadlines, cancellation, request quotas, host policy, and runtime destruction. Serializer tests cover injection, managed fields, no-content statuses, URL authority/target validation, and binary round trips. Reflected definitions receive positive and negative Luau type checks. Windows/Linux headless qualification is required; this slice introduces no platform UI or persistent endpoint.
